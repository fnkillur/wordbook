# 구글 드라이브 백업과 되살리기 설계

## 왜 만드나

폰 안에만 있는 카드·그림·발음·복습 기록은 폰을 바꾸거나 앱을 지우면 사라진다. 지금은 백업 파일을 직접 만들어 어딘가에 두어야 해서 잊기 쉽다. 하루 한 번 저절로 드라이브에 올리고, 앱 안에서 바로 되살릴 수 있게 한다.

## 정한 것 (2026-11-10 사용자 결정)

- Apps Script(발음 서버와 같은 프로젝트)를 거쳐 **하치와레 개인 드라이브**에 올린다. 폴더는 `wordbook-backup/<하치와레|우사기>/`.
- 앱을 열 때 하루 한 번 저절로 올린다. 설정에 "드라이브에 백업하기" 버튼도 있다.
- 설정의 "드라이브에서 되살리기"로 앱 안에서 되살린다.
- 파일 내보내기·가져오기는 비상용으로 그대로 둔다.

## 하지 않는 것

- 다른 사람 폴더에서 되살리기. 내 폴더만 본다.
- 드라이브에서 지난 날짜 백업 고르기. 드라이브에는 늘 마지막 상태 하나만 둔다.
- 앱에서 지운 그림·발음을 드라이브에서도 지우기. 앱에 지우는 기능이 없고, 되살릴 때는 `data.json`에 적힌 것만 쓴다.

## 실패로 보는 것

- 첫 백업이 6분 제한이나 요청 크기 때문에 끝까지 못 가는 것.
- 백업 중에 앱이 꺼졌을 때 처음부터 다시 올리는 것.
- 되살리기가 폰에 있던 더 최근 기록을 덮어쓰는 것.
- 서버를 연결하지 않았거나 인터넷이 없을 때 오류가 계속 뜨는 것.

## 방식

- 드라이브 폴더 내용
  - `data.json`: 백업 파일의 `data.json`과 같은 형식(노트·카드·복습 기록·단어 상태·어휘량 테스트·보수, 그림·발음 목록).
  - 그림·발음·문장 음성 파일 하나하나. 이름은 백업 파일의 `media/` 아래 이름과 같다.
- 올리기
  - 그림·발음은 바이트로 계산한 지문이 지난번에 올린 것과 다를 때만 올린다. 지문은 폰의 설정 표(`driveBackup`)에 둔다.
  - 여러 파일을 한 요청에 묶되, 한 요청은 3MB를 넘지 않는다.
  - 묶음 하나를 올릴 때마다 지문을 저장한다. 중간에 꺼져도 다음에 남은 것부터 올린다.
  - 그림·발음을 다 올린 뒤 `data.json`을 마지막에 올린다. 그래서 `data.json`에 적힌 파일은 드라이브에 늘 있다.
  - 같은 이름 파일이 있으면 새로 만든 뒤 예전 것은 휴지통으로 보낸다.
- 되살리기
  - `data.json`을 받아 파일 가져오기와 같은 규칙으로 합친다(더 최근 것을 남긴다).
  - 그림·발음은 가져올 노트(폰에 없거나 폰보다 최근인 것)의 것만 받는다. 3MB씩 묶어 받는다.
  - 받은 파일은 지문을 저장해 다시 올리지 않는다.
- 저절로 올리기
  - 홈을 열 때, 서버가 연결돼 있고 오늘 아직 올리지 않았으면 올린다. 실패하면 조용히 넘어가고 다음에 다시 한다.
  - 올리기와 되살리기는 한 번에 하나만 돈다.
- 설정 화면
  - "발음" 묶음을 "서버"로 바꾼다. 서버 하나가 발음과 백업을 함께 맡는다.
  - 백업 묶음에 "드라이브에 백업하기"(마지막으로 올린 때 표시)와 "드라이브에서 되살리기"를 더한다. 진행 중에는 "올리는 중 3/12"처럼 보인다.
  - 서버를 연결하지 않았으면 두 줄은 누를 수 없고, "서버를 연결하면 쓸 수 있어"라고 적는다.
- 서버
  - 요청: `backupPut`(파일 묶음 올리기), `backupList`(폴더의 파일 이름·크기), `backupGet`(파일 묶음 받기). 토큰을 확인한다.
  - 사람은 `하치와레`·`우사기`만, 파일 이름은 영문·숫자·`.`·`_`·`-`만 받는다.
  - 드라이브 권한(`https://www.googleapis.com/auth/drive`)이 더 필요하다. 배포한 뒤 사용자가 편집기에서 `checkBackup`을 한 번 실행해 허용한다.

## 빌더 판단

- 지문은 FNV-1a 32비트와 바이트 길이를 합친 값이다. 보안용이 아니라 바뀌었는지 보는 용도라 충분하다.
- 폴더 id는 스크립트 속성에 기억해 두고, 폴더를 만들 때는 스크립트 잠금을 걸어 두 번 만들지 않게 한다.
